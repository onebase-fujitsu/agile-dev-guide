# Pre-IPM

## Overview
Pre-IPM is a meeting in which draft user stories are reviewed from the Developer's perspective in preparation for the IPM (Iteration Planning Meeting).
It is held by the Product Manager, the Designer, and one pair of Developers.

## Purpose
Confirm that the user stories are sufficiently prepared for discussion and estimation at the IPM and for starting implementation.

## Frequency and Timing
- Once a week, 30–60 minutes
- Held regularly on a fixed day of the week to keep the team's rhythm
- If there are only a few target user stories, or they are unlikely to be revised based on Developer feedback, Pre-IPM and IPM are held together

## How to Run It
- The Product Manager and Designer explain the user stories to be estimated at the IPM
- The Developers review the user stories from the following perspectives
  - Is it expressed in a way that makes the value to the user understandable?
  - Is it feasible?
  - Is the story an appropriate size (does it need to be split)?
  - Is a SPIKE or investigation needed before implementing the user story?
- If changes are needed, agree on how to revise them
- (After the meeting) The Product Manager/Designer revise the user stories

{{% hint info %}}
**Tips**
- Which Developers attend is decided based on skills, the type of user story, the status of ongoing work, and so on.
{{% /hint %}}

# What is Extreme Programming

Extreme Programming (XP) is **a more practical collection of practices** for carrying out development within the agile framework, proposed by Kent Beck,
one of the members who issued the Manifesto for Agile Software Development.
Scrum defined meetings and artifacts, but it did not go as far as defining how to develop within that framework.
XP's practices complement Scrum by covering "how to develop," which Scrum does not define.

A common misconception is to see Scrum and XP as completely different schemes.
That is, "Our team does Scrum, so we can't adopt XP," or conversely, "We do XP, so we can't adopt Scrum."
This is a complete misconception. As explained in the Scrum chapter, Scrum is merely a framework for agile.
In reality, the correct picture is that development is carried out using Scrum as the framework while adopting practices such as XP.

Furthermore, in agile, the development process itself keeps being reviewed during development.
Teams take these frameworks and practices as a base and optimize them to suit each team.

Keep in mind that agile is a mindset, Scrum is a framework for developing in line with the agile mindset,
and XP is a more practical collection of practices.

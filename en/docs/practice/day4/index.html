Day 4 #

By the end of Day 3, we were able to connect the frontend built with React to the backend built with Spring Boot. However, although we can display tasks, there is still no feature for adding tasks. From Day 4 on, let’s keep adding features.

Building the Add Task Screen #

Right now, the Client application does not have a router yet. For example, accessing http://localhost:5173/ shows the Home screen, and accessing http://localhost:5173/hogehoge also shows the Home screen.

That is not very nice, so let’s implement a router. Here, we will make it so that accessing http://localhost:5173/ opens the Home screen, and accessing http://localhost:5173/newTask opens the task management screen.

Introducing a Router #

Implementing a router requires react-router-dom , so we will install it. It is a library that lets you declare even routing as part of the DOM. That description alone probably doesn’t mean much, so it will be quicker to actually see what the implementation looks like.

First, install react-router-dom.

npm install react-router-dom@^5.3.4 @types/react-router-dom@^5.3.3

Then edit App.tsx as follows.

// App.tsx
import {BrowserRouter, Route, Switch} from 'react-router-dom'
import Home from './pages/Home'

function App() {
    return (
        <div className="App">
            <BrowserRouter>
                <Switch>
                    <Route path="/" exact render={() => <Home />} />
                </Switch>
            </BrowserRouter>
        </div>
    )
}

export default App

Next, edit main.tsx as follows.

// main.tsx
import React from 'react'
import ReactDOM from 'react-dom/client'
import './index.css'
import {BrowserRouter} from 'react-router-dom'
import App from './App'
import TodoProvider from './context/TodoContext'

const root = ReactDOM.createRoot(document.getElementById('root') as HTMLElement)
root.render(
  <React.StrictMode>
    <TodoProvider>
      <BrowserRouter>
        <App />
      </BrowserRouter>
    </TodoProvider>
  </React.StrictMode>
)

In this state, accessing http://localhost:5173/ shows the Home screen. This is the same behavior as before. However, if you access http://localhost:5173/hoge , you should now see a blank white screen instead.

In other words, this is a setting that says “if the path is /, display the Home component.”

We wrote a test that checks that postTodos() receives a title as a parameter, formats it as JSON, and sends it. We also wrote a test that checks that Content-Type: application/json is set in the header.

// TodoApi.ts
import axios from 'axios'

export interface Todo {
    id: number
    title: string
    completed: boolean
}

export const getTodos = async () => {
    const response = await axios.get<Todo[]>('/todos')
    return response.data
}

export const postTodos = async (title: string) => {
    const requestJson = {title}
    const headers = {
        'X-Requested-With': 'XMLHttpRequest',
        'Content-Type': 'application/json',
    }
    const response = await axios.post<Todo>(
        '/todos',
        JSON.stringify(requestJson),
        {headers},
    )
    return response.data
}

An implementation that satisfies this test looks like this. With this, the code for calling the API is in place.

// NewTaskForm.tsx

// omitted

const NewTaskForm = () => {
    const [taskInput, setTaskInput] = useState('')
    const todoContext = useContext(TodoContext)

    const handleSend = () => {
        postTodos(taskInput)
            .then((res) =>
                todoContext?.setTodos([
                    ...todoContext.todos,
                    {
                        id: res.id,
                        title: res.title,
                        completed: res.completed,
                    },
                ]),
            )
            .catch(() => {})
    }

    return (
        <Wrapper data-testid="NewTaskForm">
            <DivForm>
                <DivLabel>
                    <Label htmlFor="titleInput">
                        Title
                        <Input
                            id="titleInput"
                            data-testid="TitleInput"
                            type="text"
                            value={taskInput}
                            onChange={(event) => setTaskInput(event.target.value)}
                        />
                    </Label>
                </DivLabel>
            </DivForm>
            <Button type="button" onClick={() => handleSend()}>
                Send
            </Button>

}

The implementation looks like this. When the button’s onClick fires, it calls handleSend, which in turn calls postTodos. It is also designed as an incremental update that adds the value returned from the server to the existing TodoContext. The fact that it is an incremental update is quite important. API design is explained later in API Design .

If you render the screen, open the creation screen, and click the Send button, you can see that the task is sent.

Changing When the Task List Is Fetched #

In the current implementation, all tasks are fetched every time the task list screen is opened. Calling the fetch-all API every time a screen is opened is inefficient. Fetching everything once at the start is enough; after that, incremental updates make processing more efficient.

The overhead of HTTP communication is incomparably larger than that of memory access or disk access. There is a term used to mock bad APIs: the “chatty API.” In other words, an API design that requires calling the API over and over again just to render a screen is not good.

Making the created task update the state incrementally earlier was also meant to avoid unnecessary communication. If POST /todos returned nothing, the client would have to call the fetch-all API just to find out the ID.

Since we have already implemented incremental updates on a successful POST, let’s change the processing from fetching all tasks every time the task list is opened to fetching all tasks only once when the app is opened.

That said, this is very easy: just move the useEffect logic from Home.tsx to App.tsx.

// App.tsx
import {Route, Routes} from 'react-router-dom'
import {useContext, useEffect} from 'react'
import Home from './pages/Home'
import NewTask from './pages/NewTask'
import {TodoContext} from './context/TodoContext'
import {getTodos} from './features/TodoApi'

const App = () => {
  const todoContext = useContext(TodoContext)

  useEffect(() => {
    const fetchData = async () => {
      const response = await getTodos()
      todoContext?.setTodos(response)
    }
    fetchData()
  }, [])

  return (
    <div className="App">
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/newTask" element={<NewTask />} />
      </Routes>
    </div>
  )
}

export default App

// Home.tsx
import React from 'react'
import styled from 'styled-components'
import TodoList from '../components/TodoList'
import Header from '../components/Header'

const Div = styled.div`
  display: flex;
`

  <Div>
    <Header />
    <TodoList />
  </Div>
)

export default Home

Prototyping #

Overview #

In prototyping, the UI of the software is designed.

The work proceeds as follows:

  • Following the scenario, consider the screen transitions and the layout of each screen
    • You may also organize the requirements to be met, and have each person make rough sketches and share them.
  • Once the rough overall picture is ready, create the UI with a tool
  • Share with the Product Manager and Developers as appropriate

Key Points of Prototyping #

  • Even before the layout has been fine-tuned, research can be done using it as a prototype. Once you confirm there are no problems, you can refine it for development
  • Build it in stages according to the hypotheses you want to validate and the iteration schedule. Don’t build all the screens at once
  • Use a tool that makes it easy to collaborate with Developers and change course (we use Figma)
  • Prepare a style guide (colors, typography), etc.
  • As much as possible, turn things into shared parts (components) from the start, aiming for a build that is resilient to change
  • UI design skills are not acquired overnight

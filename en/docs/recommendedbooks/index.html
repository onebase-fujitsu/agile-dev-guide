Recommended Books #

Here we recommend books that do not depend on any particular language or architecture.

The Art of Readable Code #

https://www.amazon.co.jp/dp/4873115655/

It hardly needs an introduction here, but it is a must-read for team development; joining product development without reading this book is like walking into someone else’s house with your shoes on.

It explains logically what readable code is. In agile development, we do not write documentation about the product (not only design documents, but also comments). Readable code itself becomes the documentation. Be sure to read it before joining product development so that you can write readable code.

The Great ScrumMaster: #ScrumMasterWay (SCRUMMASTER THE BOOK) #

https://www.amazon.co.jp/dp/4798166855/

A book that explains what a scrum master is, what a self-organizing team that acts on its own initiative looks like, and how to guide a team.

Growing Object-Oriented Software, Guided by Tests #

https://www.amazon.co.jp/dp/4798124583

Test doubles are quite a difficult concept for people who are not used to writing test code. Writing test code is very hard in the first place; it is no exaggeration to say it is harder than writing implementation code. It is a good book, although it is a pity that the test double library used in the sample code is JMock.

Beyond Legacy Code #

https://www.amazon.co.jp/dp/4873118867/

A book that says, don’t create legacy code in the first place. In this book, legacy code means “code that is hard to fix, extend, or work with.” Write test code in small units, make the behavior explicit, and then implement it. This is obvious stuff, but it lets you reaffirm the basics. This book does not contain practical, hands-on content.

Working Effectively with Legacy Code #

https://www.amazon.co.jp/dp/4798116831/

If you have legacy code in front of you right now and want to read a book about how to deal with it, read Working Effectively with Legacy Code. This book flatly declares that legacy code is code without tests. Tests are the source of everything that keeps software development moving at speed. Above all else, write tests.

Clean Architecture #

https://www.amazon.co.jp/dp/4048930656/

One of the Clean books by Uncle Bob (Robert C. Martin).

If you want to learn about the SOLID principles, you should pick up this book. It explains approaches to designing software that is resilient to change, and in agile development, which assumes change, it gives you very useful knowledge. We encourage all developers to read it.

Clean Code #

https://www.amazon.co.jp/dp/4048930591/

One of the Clean books by Uncle Bob (Robert C. Martin).

It goes deeper than The Art of Readable Code and is recommended for those who want to think about naming and conventions. It lists anti-patterns in comments, code structure, and development environments, and is good to read to elevate your code from readable code to good code.

Clean Agile #

https://www.amazon.co.jp/dp/4048930745/

One of the Clean books by Uncle Bob (Robert C. Martin), and the latest. It gives you the right mindset for agile development. As I also wrote in the In Closing chapter, it is a passionate book arguing that what is required of agile developers is craftsmanship in the pursuit of technical skill.

正しいものを正しく作る (Building the Right Thing Right) #

https://www.amazon.co.jp/dp/4802511191/

A book originally written in Japanese (quite rare in this field!) that clearly explains what it means to develop in an agile way. By reading this book, you will gain insight into the significance of confronting uncertainty through the process of hypothesis testing. It is a book to read as a team, including not only developers but also designers and product managers.

Extreme Programming Explained #

https://www.amazon.co.jp/dp/4274217620/

An explanation of Extreme Programming by Kent Beck, the founder of XP. There is probably no book more detailed than this one about the development process and team building in Extreme Programming. In agile development, everyone involved needs to be well versed in the development process. Read it before joining a project.

Test-Driven Development: By Example #

https://www.amazon.co.jp/dp/4274217884/

This is also by Kent Beck, an explanation of test-driven development. If you want to try test-driven development but wonder what kind of tests you should write, pick up this book. It makes it very clear that tests in test-driven development are about the behavior of the software.

Refactoring: Improving the Design of Existing Code #

https://www.amazon.co.jp/dp/4274224546

Martin Fowler’s book on refactoring.

It makes you sensitive to the “smells” that code gives off and able to fix them. The bad gut feeling you sometimes get when looking at code, “there’s something off here…”, is usually right. You can learn what kind of code is bad code and how to fix it.

The second edition came out in 2019, and its sample code is now in JavaScript. If you want to read it in Java, read the new edition published in 2014.

Webを支える技術 HTTP、URI、HTML、そしてREST (The Technologies That Support the Web: HTTP, URI, HTML, and REST) #

https://www.amazon.co.jp/dp/4774142042/

HTTP is the protocol that can be called the very foundation of modern web applications. This book explains what HTTP is, what URIs are, and what REST is. If you are about to get involved in web application development, we strongly encourage you to go back to basics and read it.

Web API: The Good Parts #

https://www.amazon.co.jp/dp/4873116864/

In modern web application development, Web API design skills are almost essential; not knowing them puts you out of the conversation.

What makes a good API, how should you design endpoints, what should response data look like? It is an excellent book that systematically explains this kind of knowledge about API design.

Agile Software Development, Principles, Patterns, and Practices #

https://www.amazon.co.jp/dp/4797347783/

A book by Robert C. Martin, aka Uncle Bob, familiar from the Clean series. Although the title includes “agile,” it is not a book about agile processes but about software design, and it is an excellent book covering many technical areas, from the SOLID principles to design patterns.

Java言語で学ぶデザインパターン入門 (Introduction to Design Patterns Learned in the Java Language) #

https://www.amazon.co.jp/dp/B00I8ATHGW/

Design patterns are general-purpose, reusable design patterns in object-oriented programming. Knowledge of specific programming languages and frameworks comes in and out of fashion and becomes outdated, but knowledge of design patterns and algorithms does not depend on any particular language or framework, so it offers good value for the effort.

Building Microservices #

https://www.amazon.co.jp/dp/4873117607

Any software gradually grows more complex and bloated. Microservice architecture is one approach to keeping software simple, making testing and deployment fast, and making it easy to maintain. It presents not only the advantages of microservices but also their disadvantages, and, treating monolithic architecture as one option as well, it should serve as material for considering what kind of architecture to build. We also recommend “Monolith to Microservices” and “Production-Ready Microservices,” likewise published by O’Reilly.

Peopleware #

https://www.amazon.co.jp/dp/4822285243

A book by Tom DeMarco, who has written many books on product management. In the end, it is “people” who build software. Respect “people,” and create offices where “people” can work like human beings. It is a book saying that project development requires “people” to be able to enjoy their work. It is a common story in development at Fujitsu, but I especially want people at sites that cram people into offices and rely on sheer manpower to read it. Some people may not be able to read it without tears.
